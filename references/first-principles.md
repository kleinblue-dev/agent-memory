# 第一性原理：长期记忆层为什么长这样

> 本文是 `agent-memory` 的设计契约。代码与本文冲突时以本文为准；本文与实测冲突时以实测为准，并回改本文。

## 0. 把「记忆」拆到不可再分

「agent 有记忆」不是一个大功能，是 5 个**独立**的问题，任何一个没解决都会让记忆变成负资产：

| # | 问题 | 不解决会怎样 | 本项目的答案 |
|---|---|---|---|
| M1 | 写得进、坏了不扩散 | 一条坏记录带崩整库 | 一文件一条目 + 写临时文件 rename + 坏文件跳过 |
| M2 | 找得到、且**只**找到相关的 | 召回噪声 → agent 自信地错 | 词法召回 + 硬门槛 + 预算 |
| M3 | 会变，但旧值可追溯 | 用户改了主意，agent 还在用旧值；或者旧值直接消失无法审计 | 双时态 + subject 槽位 + 取代链 |
| M4 | 不污染上下文 | 每轮塞 10 条无关记忆，钱和注意力一起烧 | top-k + token 预算 + 无命中零输出 |
| M5 | 跨工具可用 | 记忆锁死在一个插件里，换 agent 就丢 | 开放 JSON 格式 + CLI + export/import |

**推论 1：记忆的价值不在「存」，在「取代」。** 一个只会追加不会取代的系统，用三个月就会自相矛盾；而自相矛盾的记忆比没有记忆更糟。
**推论 2：召回的门槛必须高于召回的覆盖。** 漏掉一条，agent 只是少知道一点；召错一条，agent 会拿错误的用户画像做决策。
**推论 3：任何「聪明」的召回都要为同步、无网络、可复现让路。** 提示装配发生在每一轮、同步路径上，不允许等模型。

## 1. 六个不可再分的决定

### D1 · 一条记忆 = 一个文件
- 选择：`<root>/entries/<id>.json`，写临时文件再 `rename`（同卷原子）。
- 为什么不是 SQLite/向量库：目标规模 < 5k 条；单机、单用户；要求**零依赖、可 grep、可 git**；
  一条记录损坏只损失一条，不会锁库、不会写坏 WAL。
- 代价：没有事务、没有索引。接受它 —— 全量加载 5k 条 JSON 是毫秒级。

### D2 · id 由内容决定：`sha1(kind \0 lower(text))[:12]`
- 同一 kind 下同一句话（大小写/空白归一后）永远是同一 id → **天然幂等**：重复写 = 更新。
- 为什么不用自增/随机 id：重放、导入、多设备合并都会产生重复条目；内容寻址让它们自动合并。
- 代价：改一个字就是新条目 —— 这正是想要的：内容变了就是新事实，旧事实进审计链。

### D3 · 「同一条话说第二遍」= 取代，而不是新增
两条信号，从可靠到启发：
1. **显式槽位** `subject`（如「验收标准」「时区」「称呼」）：同 kind 同 subject → 旧的 `validUntil=now`、`supersededBy=新id`。
2. **同 kind 且 Jaccard ≥ 0.55 且共享 token ≥ 6**：捕获没有 subject 的改写。共享 token 少于 6 不取代（避免「都提到了 D 盘」这种巧合）。
- 额外约束：**双方都有 tags 但完全不相交 → 不取代**。tag 是主题，主题不同就不是同一句话，哪怕措辞一样。
- 从不物理删除被取代条目：`supersedes / supersededBy / validFrom / validUntil` 组成审计链。

### D4 · 召回是词法，不是语义
- 分词：CJK 按**二元组**（`记忆`→`记忆`，`我的记忆`→`的记`+`记忆`），英文/数字按词，去掉高频停用（`我的/就是/可以/the/is/...`）。
- 打分：`relevance × (0.55 + 0.45·recency) × (0.6 + 0.4·importance)`，相关性主导，时间与重要度调制。
- **硬门槛**：必须至少 1 个直接命中（权重 1）或 tag 命中；只有同义词命中（权重 0.6）→ 分数直接 0。
  没有这条，任何一句"记忆"都会召回所有含 memory 的条目，注入块变成噪音。
- 归一化用 `min(查询总权重, 条目 token 数)` 做分母（对称）：否则长用户消息永远不可匹配。
- 同义词表手工维护 18 组（中↔英）：词法召回跨不了语言，这是最便宜的桥；自动生成的别名表会注入错记忆。

### D5 · 上下文是预算，不是仓库
- 自动注入：`k=3`，`budget=300 tokens`，只放 `confidence ≥ 1`，wrapper 先扣 48 tokens，装不下就跳过（绝不截断条目）。
- 工具检索：`k ≤ 8`，`budget=800`，允许看到 `confidence=0`（人工确认用）。
- 无命中返回空串：安静的一轮 = 0 token，而不是一个空的 `<long-term-memory>` 块污染 prefix cache。

### D6 · 置信度是写者的义务
- `0=待确认 / 1=用户确认 / 2=用户明说`；自动注入只放 ≥1。
- 为什么：把"模型猜的"和"用户说的"混在一起注入，是 agent 对自己用户自信地错的根源。

## 2. 什么可以改，什么不能改

| 可以改 | 改之前要确认 |
|---|---|
| 停用词表、同义词表 | 差分测试必须仍然通过（同义词只影响排序，不影响是否命中） |
| 半衰期、重要度先验 | 只影响排序；`inject` 的 k/budget 不变时不会突然多塞 |
| 取代阈值（Jaccard/共享 token 数） | 太小会误取代（两条不同事实被合并），太大会残留旧值 |
| **不能改**：别名单独创造命中 | 改了召回立刻变噪音 |
| **不能改**：删除写墓碑而非 unlink | 改了审计链断掉，历史无法回溯 |
| **不能改**：一条文件一个条目 | 改成一个巨大 JSON，坏一个字节就丢掉全部记忆 |
| **不能改**：id 由内容决定 | 改了会导致重复条目、导入不幂等 |

## 3. 与 DSH 插件的互操作契约

- 磁盘格式（schemaVersion 2）**逐字节兼容**：插件写的条目，CLI 能读；CLI 写的条目，插件能读。
- 插件里还有两层**不在**本技能范围内：跨会话历史索引（`lib/history.js`）与提示路由（`systemPrompt.context` 装配）。
  本技能只负责「记忆本身」；宿主想自动注入，就每轮调用 `inject` 并把输出拼进 prompt（无输出就别拼）。
- 并发：单条写入是原子替换；**不要**在插件运行期间对同一目录做批量 import/export。

## 4. 验收（怎么证明它是对的）

1. **差分**：与插件原实现跑同一批输入，`tokenize/expandWeights/recall 的 id 与分数/取代链/统计`必须逐项相同（`tests/differential.test.mjs`）。
2. **幂等**：同一句话写两次，条目数不变、`createdAt` 不变。
3. **取代**：同 subject 重写后，旧的 `validUntil` 非空、新条目 `supersedes` 指向旧 id、召回只返回新的。
4. **门槛**：只用同义词（中文查英文条目）不产生命中。
5. **预算**：`inject` 的输出 token 估算 ≤ 300；无命中时输出为空。
6. **不破坏**：对真实记忆库只做只读命令，前后文件哈希必须一致。
